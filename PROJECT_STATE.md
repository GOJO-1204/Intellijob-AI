- A-14.2: Upload checks. ## Known issues
- The Privacy Policy and Terms were written by the team and not reviewed by a lawyer. The minimum age of 18 is stated in the Terms but not checked at sign up, and no fixed period is set for technical logs. Ask a teacher or someone with legal knowledge to read both pages before launch.
- The unsubscribe link changes data on a plain GET (as the registry says). A mail scanner that opens links automatically could pause someone's alerts without a click. Low severity; review in B-13.1.
- Rails writes the full request path, including the unsubscribe token, to the log (Started GET "/unsubscribe/..."). Check log filtering in B-13.1 (security).
- Seed user has a known password: delete or change it before production (Day 14)
- Adzuna redirect_url contains Adzuna's own utm_source (looks like our app_id). app_key is not in it. Low severity; review in B-13.1 (security) before putting these urls in emails.
- Gemini free tier: the model is gemini-3.1-flash-lite. Free-tier limits are unconfirmed (one guide reports about 500 requests/day for Flash-Lite). On HTTP 404 or 429, change only ResumeAiReviewer::MODEL.
- Resume text is sent to the Gemini API, and free-tier data may be used by Google to improve its products. Mention this in the README and in the security task (B-13.1).
- Development now uses Sidekiq (queue_adapter :sidekiq since B-8.1). Redis/Memurai must be running at 127.0.0.1:6379 and the worker started with: bundle exec sidekiq -q default -q mailers. Without the worker, perform_later jobs and deliver_later mails do not run. The test environment keeps its own adapter.
- SendAlertsJob sets notified_at right after the email is enqueued, not after it is delivered. If delivery fails later, those matches are not retried. Review in B-11.1 (reliability).
- After Save on the matches page the card stays on screen until a reload (the page lists only matched rows). Dashboard cards behave the same way after Save or Dismiss: they keep their place in the tab until a reload, and the empty state does not appear when the last card in a tab is dismissed (target #applications_list). Low severity; revisit in a later polish task. Turbo is now loaded on every page, so login, resume upload and preferences forms should be clicked through once (asked B).
- A job that is already in the user's Matches list cannot be added again by url with "Add a job" (the user gets the duplicate error). Low severity.
- If all 3 Gemini attempts time out, ResumeAiReviewer can take about 96 seconds (3 x 30 s plus 2 s and 4 s waits), but the results page stops polling after 90 seconds, so the tips can arrive just after it gives up. Refresh shows them. Low severity (found by B in the A-11.1 review).
- JobSources::Remotive.build has no is_a?(Hash) check (Adzuna.build has one). If Remotive ever sends one null entry in its jobs list, the whole fetch returns [] and the valid jobs are lost. Low severity. Review in the Day 14 review.
- A job embedding is not refreshed when the job description changes on a later fetch, because EmbedRecordsJob only embeds jobs whose embedding is empty. Low severity, job text rarely changes. Review in the performance review.
- Rate limits use a MemoryStore (RATE_LIMIT_STORE), which is per process and starts empty after every restart or deploy. With several Puma workers or instances each process counts on its own, so the real limit is higher than 10 uploads per hour. Review on Day 15 with hosting (Redis needs the redis gem). Not tested: what RedisCacheStore does when Redis is down (code reading says it logs and returns nil, never run).
- Check request.remote_ip on the live site (Day 15). Behind a proxy or load balancer (Render or Railway, not decided) it may show the proxy address for every user. The upload limit is per user and not affected. Any limit by IP (login, sign up, password reset, planned) would lock out everybody together if it is wrong.
- EmbedRecordsJob counts a record that fails validation as failed=1, but logs no reason (only exceptions are logged). Low severity. Review in the Day 14 review.
- A recent job with a blank title, company and description (blank embedding_text) never gets an embedding, because Embedder raises ArgumentError on blank text, so EmbedRecordsJob retries it on every run. Low severity. Review in the performance review.
- Matcher loads every recent job that has an embedding and computes the cosine similarity in Ruby. Fine for about 170 jobs, but the cost grows with the number of jobs. Low severity. Review in the performance review (Day 14).
- SendAlertsJob sorts with order(score: :desc), and Postgres puts NULL scores first. This cannot happen today, because MatchJobsJob always sets a score on the applications it creates, and no test pins it. Low severity. Review in the Day 14 review.
- A PDF with a false /Count in its page tree passes the 5 page check in ResumeParser (page_count is read first), but reading the text from it still took about 3 seconds in a manual test. The cause was not found, and it was not proven whether the page limit can be bypassed in a harmful way. Not fixed. ResumeParser.rb is 59 lines, so any change needs a split. Found in A-14.2.
